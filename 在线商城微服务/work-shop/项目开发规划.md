## 1. 项目目标与范围

### 1.1 项目目标
基于微服务架构完成在线商城系统建设，实现高可用、可扩展、可维护的电商核心能力，重点保障以下 3 个核心功能：

1. 商品选购：商品详情页需实时查询并展示可售库存。
2. 购物车：支持商品数量增减、库存校验与订单金额实时计算。
3. 订单下单-库存扣减：从购物车提交订单，确保“订单创建 + 库存扣减 + 购物车清空”分布式事务一致性（要么全部成功，要么全部回滚）。

### 1.2 范围说明
- 包含：用户、商品、库存、购物车、订单、收藏、评价、个人中心、网关、配置中心、注册中心、分布式事务、缓存、日志监控。
- 不包含：真实第三方支付对接（采用支付模拟）。

## 2. 技术方案与架构规划

### 2.1 总体技术栈
- 前端：Vue 3 + Vite + Tailwind CSS + Pinia + Vue Router
- 网关层：Nginx + API Gateway（Spring Cloud Gateway）
- 微服务：Spring Boot + Spring Cloud Alibaba
- 注册与配置中心：Nacos
- 分布式事务：Seata（AT 模式）
- 数据库：MySQL（业务库）
- 缓存：Redis
- 日志与链路：ELK 或 Loki + Promtail + Grafana，Sleuth/Zipkin（可选）

### 2.2 微服务拆分
- gateway-service：统一入口、鉴权、限流、灰度路由
- user-service：注册、登录、用户信息
- product-service：商品列表、详情、分类、搜索
- stock-service：库存查询、扣减、回滚
- cart-service：购物车增删改查、金额计算
- order-service：下单、订单状态流转、支付模拟
- favorite-service：收藏/取消收藏
- review-service：评价发布/查询
- profile-service：个人中心聚合查询

### 2.3 分层架构
1. 接入层：Web 前端 + Nginx
2. 网关层：API Gateway（鉴权、路由、限流）
3. 业务层：各业务微服务（高内聚低耦合）
4. 基础设施层：Nacos、Seata、Redis、日志平台
5. 数据层：MySQL（按服务分库分表预留）

## 4. 核心功能详细开发规划

### 4.1 核心功能一：商品选购（实时库存）

#### 4.1.1 业务目标
用户查看商品列表/详情时，可看到实时库存，避免展示过期库存。

#### 4.1.2 服务协作
- product-service 提供商品基础信息
- stock-service 提供实时库存
- 前端通过商品详情接口聚合展示

#### 4.1.3 接口规划
- `GET /api/product/list`
- `GET /api/product/detail/{productId}`
- `GET /api/stock/{productId}`
- `GET /api/product/categories`

#### 4.1.4 实时性策略
- 查询路径：Redis（库存缓存） -> MySQL（兜底）
- 缓存更新：库存扣减成功后异步刷新缓存，确保秒级一致
- 兜底机制：缓存失效时回源数据库并回填

#### 4.1.5 验收标准
- 商品详情页库存展示延迟 <= 1s（缓存刷新后）
- 商品下架时返回“商品已下架”
- 库存不足时禁止加入购物车/下单

#### 4.1.6 开发任务拆解（WBS）
1. 完成商品查询接口 DTO 与分页模型。
2. 完成库存查询接口与 Redis 缓存键设计（`stock:product:{id}`）。
3. 完成商品详情聚合逻辑（商品信息 + 实时库存）。
4. 补充缓存失效/回源逻辑及监控埋点。
5. 联调前端详情页并补充异常提示（下架、缺货、服务降级）。

### 4.2 核心功能二：购物车（增减数量 + 金额计算）

#### 4.2.1 业务目标
支持购物车商品增减、删除、勾选，实时计算总金额并进行库存校验。

#### 4.2.2 关键规则
- 购物车数据强绑定用户
- 修改数量前先校验库存上限
- 金额计算公式：

$$
订单总金额 = \sum_{i=1}^{n}(商品单价_i \times 购买数量_i)
$$

- 如有优惠扩展：

$$
应付金额 = 订单总金额 - 优惠金额 + 运费
$$

#### 4.2.3 接口规划
- `POST /api/cart/add`
- `PUT /api/cart/update`
- `DELETE /api/cart/{cartId}`
- `GET /api/cart/list`
- `DELETE /api/cart/clear`

#### 4.2.4 验收标准
- 点击 `+/-` 后 200ms~500ms 内返回新金额
- 数量超过库存返回错误码 `1001`
- 购物车总价与订单结算总价一致

#### 4.2.5 开发任务拆解（WBS）
1. 完成购物车新增、修改、删除、查询接口。
2. 完成数量增减接口的库存预检查。
3. 完成金额计算组件（单项金额、总金额、应付金额）。
4. 完成购物车勾选逻辑与结算对象过滤。
5. 增加并发修改冲突处理（最后写入时间校验或版本号）。

### 4.3 核心功能三：订单下单-库存扣减（分布式事务一致性）

#### 4.3.1 业务目标
从购物车提交订单时，确保订单、库存、购物车三方数据一致。

#### 4.3.2 事务流程（UC003）
1. 用户提交购物车结算请求。
2. order-service 校验购物车与库存。
3. 开启 Seata 全局事务。
4. 创建订单主表与订单明细。
5. 调用 stock-service 扣减库存。
6. 调用 cart-service 清理已下单购物车项。
7. 全部成功后提交事务；任一步失败触发全局回滚。

#### 4.3.3 异常场景
- 库存不足：返回 `1001`，订单不落库或状态回滚。
- 服务超时：触发 Seata 回滚，保证无脏数据。
- 重复提交：订单幂等校验（requestId/orderToken）。

#### 4.3.4 接口规划
- `POST /api/order/submit`
- `POST /api/stock/deduct`
- `POST /api/stock/rollback`

#### 4.3.5 验收标准
- 压测并发场景下无超卖
- 回滚成功率 100%
- 订单与库存数据最终一致

#### 4.3.6 关键实现约束（必须遵守）
1. 在 `order-service` 下单方法标注全局事务入口。
2. 先落订单草稿，再调用库存扣减与购物车清理。
3. 分支服务抛出业务异常时，必须向上透传，禁止吞异常。
4. 下单接口必须做幂等：`orderToken` 一次性消费或 `requestId` 去重。
5. 对库存不足、商品下架、购物车为空分别返回标准错误码（`1001`/`1003`/`3001`）。

## 5. API 与网关规划

### 5.1 统一规范
- 协议：HTTP/HTTPS
- 格式：JSON
- 响应体：`{code, message, data}`
- 认证：JWT（Bearer Token）
- 请求头：`X-User-Id`（所有接口都需要）

### 5.2 网关能力
- 路由转发：按 `/api/{service}` 前缀路由
- 鉴权拦截：个人中心、订单、收藏、评价必须登录
- 限流：
  - 单 IP：10 req/s
  - 下单接口：5 req/min
- 降级：服务不可用返回友好提示 `503`

### 5.3 Nginx 规划
- 配置文件：mall-nginx.conf
- 默认端口：80
- 关键能力：反向代理、负载均衡、静态资源托管、访问日志/错误日志

### 5.4 Nginx 路由与安全落地清单（来自规则文件）
1. 静态资源：前端产物统一放在 Nginx 根目录，首页默认 `index.html`。
2. API 转发：`/api/product/**`、`/api/order/**`、`/api/favorite/**` 路由到对应网关/服务。
3. 未登录访问控制：个人中心、订单、收藏页面入口前置鉴权，未登录跳转登录页。
4. IP 限流：单 IP 10 req/s，下单接口单用户 5 req/min（网关配合实现）。
5. 敏感资源阻断：禁止访问配置文件、备份文件、隐藏目录。
6. 服务容错：后端故障返回友好 JSON 提示，不直接暴露网关堆栈。
7. 日志策略：开启 access/error 日志，按周切分并保留最近 30 天。

### 5.5 Nginx 配置样例（可直接改造）
```nginx
upstream mall_gateway {
  server 127.0.0.1:8080 max_fails=3 fail_timeout=30s;
}

limit_req_zone $binary_remote_addr zone=ip_limit:10m rate=10r/s;

server {
  listen 80;
  server_name _;
  root /data/mall/web;
  index index.html;

  access_log logs/mall.access.log;
  error_log logs/mall.error.log warn;

  location / {
    try_files $uri $uri/ /index.html;
  }

  location /api/ {
    limit_req zone=ip_limit burst=20 nodelay;
    proxy_pass http://mall_gateway;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_connect_timeout 3s;
    proxy_read_timeout 10s;
  }

  location ~* /(\.git|\.env|backup|config|.*\.sql)$ {
    deny all;
    return 403;
  }
}
```

## 9. 风险与应对

1. 风险：高并发超卖
- 应对：库存乐观锁 + Redis 预扣 + Seata 回滚兜底

2. 风险：分布式事务性能开销
- 应对：仅在核心链路启用全局事务，减少事务范围

3. 风险：服务雪崩
- 应对：网关限流、熔断降级、超时重试、隔离舱

4. 风险：敏感信息泄露
- 应对：生产环境使用配置中心加密，不明文存储数据库密码

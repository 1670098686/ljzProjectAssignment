# 失物招领小程序需求规格说明书

## 1. 项目概述

### 1.1 项目背景

随着校园生活的多样化，学生和老师在校园内丢失物品的情况时有发生。传统的失物招领方式存在信息分散、沟通不畅、管理困难等问题，导致失物找回率低，归还物品流程复杂。为了解决这些问题，开发一款校园失物招领小程序，为用户提供便捷的寻物和拾物信息发布平台，同时为管理员提供信息审核和管理工具，从而提高失物找回效率，促进校园互助氛围。

### 1.2 项目目标

- 为用户提供快速发布寻物信息和拾物信息的平台
- 为用户提供查看和搜索失物招领信息的便捷渠道
- 为用户提供安全、高效的小程序内沟通渠道
- 为管理员提供信息审核、用户管理和数据统计的功能
- 提高校园内物品的找回率，减少资源浪费
- 建立安全、高效、有序的校园失物招领生态系统

### 1.3 项目范围

本项目为校园失物招领小程序，不使用微信云开发，采用传统的前后端分离架构。主要功能包括：物品信息发布、信息审核、信息展示、用户沟通、状态管理、数据统计等。

## 2. 功能需求（Functional Requirements）

### 2.1 用户角色

| 角色  | 特征      | 核心需求                                   |
| --- | ------- | -------------------------------------- |
| 用户  | 在校学生/老师 | 既可以使用失主功能发布寻物信息，也可以使用拾主功能发布拾物信息，安全联系对方 |
| 管理员 | 小程序管理员  | 审核信息、管理用户、处理投诉、统计数据                    |

**说明**：所有用户成员（学生/老师）既可以使用失主功能，又可以使用拾主功能，无需区分特定角色。

### 2.2 功能模块

#### 2.2.1 公共模块

- **用户登录/注册**：基于微信登录，获取用户基本信息，添加学生、老师、管理员的身份验证，验证方式为学业邮箱
- **首页**：展示最新捡到物品和丢失物品列表
- **搜索功能**：按物品名称、类型、地点等搜索物品信息
- **消息通知**：系统消息、审核结果通知、用户间沟通消息

#### 2.2.2 用户功能

- **发布寻物信息**：填写物品名称、类型、丢失时间、地点、特征、照片等，发布丢失物品信息
- **发布拾物信息**：填写物品名称、类型、捡到时间、地点、特征、照片等，发布捡到物品信息
- **查看发布记录**：管理已发布的寻物和拾物信息
- **编辑发布信息**：修改已发布但未完成的信息
- **标记物品状态**：确认物品找回或归还后更新状态
- **消息沟通**：通过平台内置消息系统与信息发布者沟通

#### 2.2.3 管理员功能

- **信息审核**：审核寻物和拾物信息，判断是否真实、是否有诈骗/广告/敏感信息
- **信息管理**：管理已发布的信息，处理用户投诉和举报
- **用户管理**：查看用户信息，处理违规用户
- **数据统计**：统计招领数据，包括发布数量、成功找回数量等
- **系统管理**：维护平台安全与正常运行

## 3. 非功能需求（Non-Functional Requirements）

### 3.1 性能需求

- 页面加载时间：首页加载时间不超过3秒
- 响应时间：用户操作响应时间不超过1秒
- 并发处理：支持同时1000用户在线操作

### 3.2 安全需求

- 数据传输加密：所有用户数据和通信采用HTTPS加密
- 用户认证：基于微信小程序的登录认证机制
- 信息审核：所有发布信息必须经过管理员审核才能上线
- 隐私保护：用户联系方式（电话、微信）默认脱敏显示，仅发布者本人可见完整信息；用户间主要通过小程序内消息系统联系

### 3.3 可用性需求

- 界面友好：操作简单直观，符合微信小程序设计规范
- 错误处理：提供清晰的错误提示和处理机制
- 兼容性：支持主流微信版本和设备

### 3.4 可维护性需求

- 代码结构清晰：采用模块化设计，便于维护和扩展
- 文档完整：提供详细的开发文档和用户手册
- 日志记录：记录系统操作日志，便于问题排查

## 4. 数据需求

### 4.1 数据实体

- **用户信息**：用户ID、微信昵称、头像、角色类型
- **寻物信息**：寻物ID、用户ID、物品名称、类型、丢失时间、地点、特征、联系人姓名、联系电话、联系微信、照片、状态、发布时间、审核状态
- **拾物信息**：拾物ID、用户ID、物品名称、捡到时间、地点、特征、联系人姓名、联系电话、联系微信、照片、状态、发布时间、审核状态
- **消息记录**：消息ID、发送者ID、接收者ID、内容、发送时间、状态
- **投诉记录**：投诉ID、投诉人ID、被投诉信息ID、投诉原因、处理状态、处理时间

### 4.2 数据存储

- 采用MySQL数据库存储结构化数据
- 采用文件服务器存储图片等非结构化数据
- 数据备份：定期备份数据库和文件

## 5. 界面设计

### 5.1 设计原则

- 简洁明了：界面设计简洁，重点突出信息展示
- 一致性：遵循微信小程序设计规范，保持界面风格一致
- 易用性：操作流程简单直观，减少用户学习成本
- 美观性：视觉效果舒适，符合现代设计趋势

### 5.2 主要页面

#### 5.2.1 登录注册页面

- **布局设计**：
  - 登录页面：顶部Logo、中部登录表单（学业邮箱、密码）、底部注册入口
  - 注册页面：顶部返回按钮、中部注册表单（学业邮箱、邮箱验证码、密码、昵称、身份选择）、底部登录入口
- **功能**：
  - 登录功能：输入学业邮箱和密码进行登录；绑定微信号后可以一键登录
  - 注册功能：绑定当前微信号，选择身份（学生、教师、管理员），输入学业邮箱进行验证
  - 邮箱验证：发送验证码到学业邮箱（演示模式固定验证码 123456），验证通过后方可完成注册
  - 注册成功后返回登录页面进行登录
  - 微信登录：wx.login 获取 code 发送至后端换取 token（演示模式下直接登录 admin 账号）
- **交互**：
  - 点击登录按钮进行登录验证
  - 点击注册按钮跳转到注册页面
  - 注册时选择身份（学生、教师、管理员）
  - 发送邮箱验证码并验证
  - 注册成功后自动返回登录页面

#### 5.2.2 首页

- **布局设计**：
  - 顶部：标签页切换（捡到物品/丢失物品）
  - 中部：搜索栏（支持按物品名称、类型、地点搜索）和筛选区（支持按照类型、时间、地点筛选）
  - 下方：信息列表（卡片式布局，展示物品图片、名称、地点、时间等关键信息）
  - 底部：导航栏（首页、发布、消息、我的）
- **功能**：
  - 浏览最新捡到/丢失物品信息
  - 快速搜索物品
  - 点击卡片进入详情页
  - 通过底部导航栏切换到其他页面
- **交互**：
  - 下拉刷新获取最新信息
  - 上拉加载更多信息
  - 点击标签页切换显示内容
  - 点击底部导航栏切换页面

#### 5.2.3 发布页面

- **布局设计**：
  - 顶部：标签页切换（寻物/拾物）
  - 中部：表单区域
  - 底部：导航栏（首页、发布、消息、我的）
- **功能**：
  - 发布寻物信息：填写物品名称、类型、丢失时间、地点、特征、上传照片
  - 发布拾物信息：填写物品名称、类型、捡到时间、地点、特征、上传照片
  - 通过底部导航栏切换到其他页面
- **交互**：
  - 实时表单验证
  - 图片选择与预览
  - 提交后显示审核状态
  - 点击底部导航栏切换页面

#### 5.2.4 详情页面

- **布局设计**：
  - 顶部：物品名称标题+返回按钮+分享链接功能
  - 中部：物品图片轮播、物品信息（名称、类型、时间、地点、特征）
  - 底部：操作按钮（发消息、举报）
- **功能**：
  - 查看物品详细信息
  - 通过小程序内消息系统与发布者沟通
  - 举报违规信息
- **交互**：
  - 图片轮播查看
  - 点击发消息按钮进入消息聊天页面
  - 点击举报按钮提交举报信息
- **进入方式**：通过点击首页消息列表中的信息进入

#### 5.2.5 个人中心

- **布局设计**：
  - 顶部：用户头像、昵称、角色、个人签名
  - 中部：功能菜单（我的发布、我的消息、设置、管理员后台入口）
  - 下方：其他功能入口（关于我们、帮助中心）
  - 底部：导航栏（首页、发布、消息、我的）
- **功能**：
  - 查看个人信息
  - 管理发布记录（寻物/拾物）
  - 查看消息通知
  - 修改个人设置
  - 管理员后台入口（仅管理员身份可见）
  - 通过底部导航栏切换到其他页面
- **交互**：
  - 点击菜单进入对应功能页面
  - 长按发布记录进行编辑/删除操作
  - 点击底部导航栏切换页面

#### 5.2.5 消息页面

- **布局设计**：
  - 顶部：页面标题
  - 中部：消息列表（系统通知 + 会话列表，两个 Tab 切换）
  - 底部：导航栏（首页、发布、消息、我的）
- **功能**：
  - 查看系统通知（审核结果、平台公告、新消息提醒）
  - 与其他用户进行消息沟通
  - 发送文字、图片消息
  - 未读消息红点提示
  - 通过底部导航栏切换到其他页面
- **交互**：
  - 点击消息进入聊天界面
  - 下拉刷新获取最新消息
  - 输入文字发送消息
  - 点击底部导航栏切换页面

#### 5.2.6 管理员后台

- **布局设计**：
  - 个人中心入口（仅管理员可见入口菜单）
  - 审核列表页：展示待审核信息、已审核信息两个 Tab
  - 审核详情页：显示信息详情，通过/驳回操作，填写驳回原因
  - 举报管理页：举报列表，处理违规举报
  - 用户管理页：用户列表，启用/禁用用户
  - 统计中心页：总览数据（发布量、找回率、审核通过率）、按时间/分类趋势图
  - 发送通知页：面向全部用户或指定用户发送系统通知
- **功能**：
  - 审核寻物/拾物信息（通过/驳回，可填写驳回原因）
  - 管理已发布信息（下架/恢复）
  - 查看用户信息，处理违规用户（启用/禁用）
  - 查看数据统计报表
  - 批量发送系统通知
- **交互**：
  - 审核列表支持 Tab 切换（待审核/已审核）
  - 举报列表支持按状态筛选
  - 统计页支持按时间段查看数据趋势
  - 发送通知支持填写标题与内容，提交后全站用户接收
- **访问方式**：管理员身份的用户登录后在个人中心页面进入对应功能

### 5.3 交互设计

- 表单提交：实时验证，提供友好的错误提示
- 图片上传：支持多张图片选择和预览
- 消息沟通：内置消息系统，支持实时消息提醒
- 状态更新：物品状态变更时提供视觉反馈

## 6. 技术架构

### 6.1 前端技术

- 微信小程序原生开发
- WXML + WXSS + JavaScript
- 第三方组件库：Vant Weapp

### 6.2 后端技术

- 语言：Node.js
- 框架：Express
- 数据库：MySQL
- 缓存：Redis
- 文件存储：本地文件系统或对象存储服务

### 6.3 系统架构

- 前后端分离架构
- 前端：微信小程序客户端
- 后端：API服务
- 数据库：数据存储
- 文件存储：图片等静态资源存储

### 6.4 关键技术点

- 微信登录认证
- 图片上传与处理
- 消息系统实现
- 信息审核流程
- 数据统计与分析

## 9. 技术选型理由

### 9.1 前端技术

- **微信小程序原生开发**：直接使用微信小程序框架，无需额外学习成本，与微信生态深度集成
- **WXML + WXSS + JavaScript**：微信小程序的标准开发语言，简单易用，功能强大
- **Vant Weapp**：轻量级UI组件库，提供丰富的组件，加速开发效率，提升界面美观度

### 9.2 后端技术

- **Node.js**：事件驱动、非阻塞I/O，适合处理高并发请求，开发效率高
- **Express**：轻量级Web框架，路由管理灵活，中间件丰富，易于扩展
- **MySQL**：关系型数据库，稳定可靠，适合存储结构化数据，社区支持广泛
- **Redis**：内存数据库，用于缓存热点数据，提高系统响应速度
- **本地文件系统**：用于存储图片等非结构化数据，部署简单，适合小规模应用

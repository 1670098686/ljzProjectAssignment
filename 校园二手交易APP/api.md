# 校园二手交易APP后端API接口规范

## 1. 概述

### 1.1 文档目的
本文档定义了校园二手交易APP后端API接口的设计规范、接口定义和使用说明，旨在为前端开发、后端开发和测试人员提供统一的接口参考。

### 1.2 接口设计原则
- **RESTful风格**：采用标准的HTTP方法和状态码
- **统一响应格式**：所有接口返回统一的数据格式
- **版本控制**：API路径包含版本号
- **安全性**：实现身份认证和权限控制
- **可扩展性**：支持未来功能扩展

### 1.3 基础URL
```
http://localhost:8080/api/v1
```

## 2. 统一响应格式

### 2.1 成功响应
```json
{
  "code": 200,
  "message": "请求成功",
  "data": {}
}
```

### 2.2 失败响应
```json
{
  "code": 500,
  "message": "请求失败",
  "data": null
}
```

### 2.3 分页响应
```json
{
  "code": 200,
  "message": "请求成功",
  "data": {
    "items": [],
    "meta": {
      "page": 1,
      "size": 10,
      "total": 100
    }
  }
}
```

## 3. 认证与授权

### 3.1 JWT Token认证
- **请求头**：`Authorization: Bearer {token}`
- **过期时间**：24小时
- **刷新机制**：支持Token刷新

### 3.2 接口权限
| 角色 | 权限范围 |
|------|----------|
| 普通用户 | 基础功能访问 |
| 管理员 | 管理后台访问 |

## 4. API接口列表

### 4.1 认证相关接口

#### 4.1.1 用户登录
- **URL**：`/auth/login`
- **方法**：`POST`
- **请求体**：
  ```json
  {
    "username": "string",
    "password": "string"
  }
  ```
- **响应体**：
  ```json
  {
    "code": 200,
    "message": "登录成功",
    "data": {
      "token": "string",
      "user": {
        "id": 1,
        "username": "string",
        "email": "string",
        "role": "USER"
      }
    }
  }
  ```

#### 4.1.2 用户注册
- **URL**：`/auth/register`
- **方法**：`POST`
- **请求体**：
  ```json
  {
    "username": "string",
    "password": "string",
    "email": "string",
    "phone": "string"
  }
  ```
- **响应体**：
  ```json
  {
    "code": 200,
    "message": "注册成功",
    "data": {
      "id": 1,
      "username": "string"
    }
  }
  ```

### 4.2 商品相关接口

#### 4.2.1 获取商品列表
- **URL**：`/products`
- **方法**：`GET`
- **查询参数**：
  - `page`: 页码，默认1
  - `size`: 每页数量，默认10
  - `category`: 分类ID
  - `keyword`: 搜索关键词
  - `minPrice`: 最低价格
  - `maxPrice`: 最高价格
- **响应体**：分页商品列表

#### 4.2.2 获取商品详情
- **URL**：`/products/{id}`
- **方法**：`GET`
- **路径参数**：
  - `id`: 商品ID
- **响应体**：商品详情

#### 4.2.3 发布商品
- **URL**：`/products`
- **方法**：`POST`
- **请求体**：
  ```json
  {
    "title": "商品标题",
    "price": 99.9,
    "description": "商品描述",
    "category": "CATEGORY_1",
    "images": ["url1", "url2"],
    "location": "交易地点",
    "contactInfo": "联系方式"
  }
  ```
- **响应体**：创建的商品详情

#### 4.2.4 更新商品
- **URL**：`/products/{id}`
- **方法**：`PUT`
- **路径参数**：
  - `id`: 商品ID
- **请求体**：
  ```json
  {
    "title": "更新后的商品标题",
    "price": 89.9,
    "description": "更新后的商品描述",
    "images": ["url1", "url2", "url3"],
    "location": "更新后的交易地点",
    "contactInfo": "更新后的联系方式"
  }
  ```
- **响应体**：更新后的商品详情

#### 4.2.5 删除商品
- **URL**：`/products/{id}`
- **方法**：`DELETE`
- **路径参数**：
  - `id`: 商品ID
- **响应体**：删除结果

## 5. 错误码定义

| 错误码 | 描述 |
|--------|------|
| 200 | 请求成功 |
| 400 | 请求参数错误 |
| 401 | 未授权 |
| 403 | 禁止访问 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |
| 5001 | 用户名或密码错误 |
| 5002 | 用户已存在 |
| 5003 | 商品不存在 |
| 5004 | 订单不存在 |
| 5005 | 库存不足 |
| 5006 | 支付失败 |
| 5007 | 权限不足 |
| 5008 | 请勿重复举报同一内容，正在处理中 |
| 5009 | 仅允许将举报置为已处理或已驳回 |
| 5010 | 消息不存在 |
| 5011 | 无权举报该消息 |
| 5012 | 地址不存在 |
| 5013 | 分类不存在 |
| 5014 | 文件上传失败 |

## 6. 最佳实践

- 合理设置请求超时时间
- 实现重试机制处理网络异常

### 6.2 错误处理
- 统一处理HTTP错误码
- 对不同错误类型进行分类处理
- 给用户提供友好的错误提示

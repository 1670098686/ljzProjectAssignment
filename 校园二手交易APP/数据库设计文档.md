## 1. 背景与目标

- **项目定位**：面向校园场景的「简单但功能齐全」二手交易平台，客户端为 Android 原生（Java），后端基于 Spring Boot 3.x。
- **数据职责**：承载用户、商品、订单、消息、管理员等五大核心域模型，满足注册登录、商品发布、下单沟通、后台审核等主链路。
- **交付要求**：设计清晰、易于讲解；字段命名统一；支持后续扩展（收藏、举报、统计等）。

## 2. 设计原则与运行环境

| 类别 | 约定 |
| --- | --- |
| 规范化 | 满足第三范式，必要时通过 JSON 扩展字段减少表数量，保持实现简单 |
| 一致性 | 所有时间列统一使用 `datetime`，命名为 `*_time`; 金额统一 `decimal(10,2)` |
| 安全性 | 敏感字段（密码、权限）加密或最小化暴露；所有外键开启 InnoDB 约束 |
| 性能 | 典型查询字段提供单列或复合索引，分页查询默认 10 条/页 |
| 可维护性 | 通过 Flyway 维护版本，命名遵循英文字母小写 + 下划线 |

**环境配置**：

| 项 | 值 |
| --- | --- |
| 数据库 | MySQL 8.0+ (`ai`) |
| 账号/密码 | `test` / 空 |
| 端口 | 3306 |
| 字符集/排序规则 | `utf8mb4` / `utf8mb4_unicode_ci` |
| 连接参数 | `useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=Asia/Shanghai` |

## 3. 命名规范与通用字段

1. **命名风格**：
     - 表名使用复数（`users`, `products`）。
     - 主键统一为 `id`，外键命名 `{entity}_id`（如 `seller_id`）。
     - 枚举字段直接存储大写字符串（如 `status='PENDING_PAYMENT'`）。
2. **通用列**：

| 列名 | 类型 | 说明 |
| --- | --- | --- |
| `create_time` | datetime | 创建时间，默认 `CURRENT_TIMESTAMP` |
| `update_time` | datetime | 更新时间，`ON UPDATE CURRENT_TIMESTAMP` |
| `status` | varchar(20) | 根据业务选择枚举类型 |
| `remark` | varchar(200) | 可选扩展备注列，默认空 |

3. **逻辑删除**：当前版本通过业务状态（如 `products.status='DELETED'` 代表已删除）实现，无额外 `deleted` 列，保持实现简单。

## 5. 核心表设计（已实现）

### 5.1 用户表 `users`（基于实际 User 实体类，已实现）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | bigint | PK, AI | 用户唯一 ID |
| `username` | varchar(50) | UQ, NOT NULL | 用户名（3-20 个字符） |
| `password` | varchar(100) | NOT NULL | BCrypt 哈希 |
| `email` | varchar(100) | UQ, NOT NULL | 作为登录凭证之一 |
| `phone` | varchar(20) | NULL | 便于交易沟通 |
| `real_name` | varchar(50) | NULL | 可用于实名认证扩展 |
| `school` | varchar(100) | NULL | 学校或院系 |
| `avatar` | varchar(200) | NULL | 静态资源路径 |
| `contact_info` | varchar(100) | NULL | 联系方式信息 |
| `role` | varchar(20) | 默认 `STUDENT` | `STUDENT/TEACHER/STAFF`（基于 UserRole 枚举） |
| `status` | varchar(20) | 默认 `ACTIVE` | `ACTIVE/DISABLED`（基于 AccountStatus 枚举） |
| `email_verified` | boolean | 默认 `false` | 邮箱是否已验证 |
| `delete_requested` | boolean | 默认 `false` | 账号注销流程标记 |
| `delete_reason` | varchar(200) | NULL | 用户填写的注销原因 |
| `delete_schedule_time` | datetime | NULL | 定时彻底删除时间 |
| `last_login` | datetime | NULL | 最近一次成功登录 |
| `create_time` | datetime | | 创建时间 |
| `update_time` | datetime | | 更新时间 |

**索引**：`PRIMARY(id)`、`UNIQUE(username)`、`UNIQUE(email)`、`idx_role_status(role,status)`、`idx_email_verified(email_verified)`、`idx_delete_requested(delete_requested)`。

**业务要点**：
- 登录需校验 `status='ACTIVE' && email_verified=true`。
- 账号注销：`delete_requested=true` 且 `delete_schedule_time` 超期后由定时任务自动置为 `status='DISABLED'` 并清空联系方式等敏感字段。

### 5.2 商品表 `products`（基于实际 Product 实体类，已实现）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | bigint | PK, AI | 商品 ID |
| `title` | varchar(200) | NOT NULL | 商品标题，支持全文索引 |
| `description` | text | NULL | 详情描述 |
| `price` | decimal(10,2) | NOT NULL | 成交单价 |
| `category` | varchar(20) | 默认 `BOOKS` | `BOOKS/ELECTRONICS/CLOTHING/SPORTS/DAILY/OTHER`（基于 ProductCategory 枚举） |
| `images` | json | NULL | 图片 URL 数组（使用 JsonListConverter 转换） |
| `seller_id` | bigint | FK → `users.id` | 发布者 |
| `status` | varchar(20) | 默认 `ON_SALE` | `ON_SALE/OFF_SALE/SOLD/DELETED`（基于 ProductStatus 枚举） |
| `audit_status` | varchar(20) | 默认 `PENDING` | `PENDING/APPROVED/REJECTED`（基于 AuditStatus 枚举） |
| `view_count` | int | 默认 `0` | 浏览量 |
| `like_count` | int | 默认 `0` | 点赞/收藏数 |
| `contact_info` | varchar(100) | NULL | 线下联系方式 |
| `location` | varchar(100) | NULL | 面交地点 |
| `remark` | varchar(200) | NULL | 审核备注或系统提示 |
| `create_time` | datetime | | 创建时间 |
| `update_time` | datetime | | 更新时间 |

**索引**：`idx_seller_status(seller_id,status)`、`idx_category_status(category,status)`、`idx_price(price)`、`idx_audit_status(audit_status)`、全文索引 `ft_title_desc(title,description)`。

**业务要点**：
- 发布商品默认 `status='ON_SALE'`、`audit_status='PENDING'`，管理员审核通过后同步置为 `APPROVED`。
- 当 `status='DELETED'` 时视为逻辑删除，接口层过滤。
- `images` 字段采用 JSON 数组，便于在 Android 端直接解析。

| `payment_status` | varchar(20) | 默认 `NOT_INITIATED` | `NOT_INITIATED/PENDING/PROCESSING/SUCCEEDED/FAILED/EXPIRED/CANCELLED/REFUND_PENDING/REFUNDED`（基于 PaymentStatus 枚举） |

| `buyer_note` | varchar(200) | NULL | 买家备注 |
| `seller_note` | varchar(200) | NULL | 卖家备注 |
| `buyer_rating` | tinyint | NULL | 1-5 星买家评价 |
| `buyer_comment` | varchar(300) | NULL | 买家评价内容 |
| `seller_rating` | tinyint | NULL | 1-5 星卖家评价 |
| `seller_comment` | varchar(300) | NULL | 卖家评价内容 |
| `refund_status` | varchar(20) | 默认 `NONE` | 退款状态 |
| `refund_time` | datetime | NULL | 退款时间 |
| `create_time` | datetime | | 创建时间 |
| `update_time` | datetime | | 更新时间 |

**索引**：`idx_order_no(order_no)`、`idx_buyer_status(buyer_id,status)`、`idx_seller_status(seller_id,status)`、`idx_product(product_id)`、`idx_payment_status(payment_status)`。

**业务要点**：
- 订单号生成规则：`yyyyMMddHHmmss` + 6 位随机数。
- 订单状态流转：PENDING_PAYMENT → PENDING_SHIPMENT → PENDING_RECEIPT → COMPLETED。
- 支付状态与订单状态独立，支持支付失败后重试。

```sql
CREATE TABLE `users` (
    `id` bigint NOT NULL AUTO_INCREMENT,

    `phone` varchar(20) DEFAULT NULL,
    `real_name` varchar(50) DEFAULT NULL,
    `school` varchar(100) DEFAULT NULL,
    `avatar` varchar(200) DEFAULT NULL,
    `contact_info` varchar(100) DEFAULT NULL,
    `role` varchar(20) NOT NULL DEFAULT 'STUDENT',

) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

> **提示**：将上述 SQL 拆分为多个 Flyway 迁移脚本（如 `V1__init_users.sql`）更利于课堂演示和版本化管理。

## 8. 性能与维护建议（已实施）

1. **索引策略**：
     - 高频筛选字段使用复合索引（如 `category + status`）。
     - 长文本字段仅在必要时创建全文索引，避免影响写入性能。
2. **查询优化**：
     - Android 端分页默认 `page=1,size=10`，禁止一次性拉取全部数据。
     - 大列表接口先查 ID 再回表（或直接覆盖索引），减少磁盘 IO。
3. **数据分层**：
     - 热数据：近 90 天订单、商品放在主表。
     - 温/冷数据：可按月份拆分归档表（`orders_2025_01`），或导出到对象存储。

## 9. 项目总结（已完成）

- **最小权限账号**：`test` 仅授予 CRUD，生产环境应拆分读写账号。
- **加密与脱敏**：密码使用 BCrypt，导出日志时脱敏手机号/邮箱。
- **备份策略**：每周全量 + 每日增量，保留 90 天，月度执行恢复演练。
- **审计**：开启 MySQL `general_log` 或使用 Binlog 审计关键 DDL/DML。

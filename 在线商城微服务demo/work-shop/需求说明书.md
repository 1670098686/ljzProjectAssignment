一、项目概述
本项目为基于微服务架构的在线商城系统，面向普通用户提供商品浏览、选购、加购、下单、支付、评价、收藏等全流程电商能力。系统采用微服务拆分，保证高可用、易扩展、分布式事务安全，满足多用户并发访问与库存一致性要求。
核心功能：商品选购（实时库存）、购物车（增删改数量、自动计价）、订单创建 + 库存扣减（分布式事务一致性）
附加功能：商品收藏、商品评价、个人中心
二、功能需求分析
2.1 功能需求文字描述
2.1.1 用户模块
用户可注册、登录、退出、修改个人信息，系统识别用户身份用于购物车、订单、收藏、评价。
2.1.2 商品模块
1. 展示商品列表、详情
2. 实时显示库存数量
3. 支持按分类、关键词搜索
2.1.3 购物车模块
1. 添加商品到购物车
2. 修改购买数量（增/减）
3. 移除商品
4. 自动计算商品总价、订单金额
5. 购物车数据与用户绑定
2.1.4 订单模块
1. 从购物车批量提交生成订单
2. 展示订单信息
3. 支持支付模拟
4. 下单时自动扣减库存
5. 保证分布式事务：订单创建成功的同时，库存扣减成功（要么都成功，要么都回滚）
2.1.5 收藏模块
1. 用户收藏/取消收藏商品
2. 查看我的收藏列表
2.1.6 评价模块
1. 对已完成订单的商品发表评价
2. 查看商品所有评价

2.3 用例规约
2.3.1 核心业务用例
用例规约1：查看商品详情（含实时库存）
用例编号：UC001
用例名称：查看商品详情
参与者：用户
前置条件：用户进入商品列表
后置条件：显示商品信息与最新库存
基本流程：
(1)用户点击某一商品
(2)系统请求商品服务获取商品信息
(3)系统请求库存服务获取实时库存数量
(4)系统展示商品详情 + 库存
异常流程：
(1)商品不存在 → 提示 “商品已下架”
用例规约2：修改购物车商品数量
用例编号：UC002
用例名称：修改购物车数量
参与者：用户
前置条件：用户已登录，购物车有商品
后置条件：购物车数量更新，金额重新计算
基本流程：
(1)用户进入购物车
(2)点击 + /- 修改数量
(3)系统校验库存是否充足
(4)更新购物车数量
(5)重新计算单项金额与订单总金额
异常流程：
(1)购买数量 > 库存 → 提示 “库存不足”
用例规约3：提交订单（含库存扣减与分布式事务）
用例编号：UC003
用例名称：购物车提交订单
参与者：用户
前置条件：用户已登录，购物车非空
后置条件：生成订单，扣减库存，购物车清空
基本流程：
(1)用户点击 “结算”
(2)系统校验商品库存
(3)开启分布式事务
(4)创建订单
(5)扣减库存
(6)清空购物车
(7)提交事务，全部成功
异常流程：
(1)库存不足 → 订单回滚，库存回滚
(2)服务异常 → 分布式事务自动回滚，保证数据一致
2.3.2 非核心业务用例
用例规约4：个人中心信息管理
用例编号：UC004
用例名称：个人中心信息管理
参与者：用户
前置条件：用户已成功登录系统
后置条件：用户信息更新成功或订单 / 收藏 / 评价列表正常展示
基本流程：
(1)用户点击进入 “个人中心”
(2)系统展示个人信息、我的订单、我的收藏、我的评价等入口
(3)用户可选择查看个人基本资料
(4)用户可修改昵称、头像、手机号、收货地址等信息
(5)系统校验信息格式合法性
(6)信息保存成功，页面刷新并提示操作成功
异常流程：
(1)未登录状态访问 → 跳转至登录页面
(2)手机号格式不合法 → 提示 “请输入正确手机号”
(3)网络异常导致保存失败 → 提示 “保存失败，请稍后重试”
用例规约5：商品收藏与取消收藏
用例编号：UC005
用例名称：商品收藏 / 取消收藏
参与者：用户
前置条件：用户已登录，进入商品详情页
后置条件：收藏状态变更，收藏列表同步更新
基本流程：
(1)用户在商品详情页点击 “收藏” 按钮
(2)系统校验用户登录状态
(3)系统向收藏服务发起请求，添加该商品至用户收藏列表
(4)页面按钮状态变为 “已收藏”
(5)用户再次点击可执行 “取消收藏”
(6)系统删除对应收藏记录，按钮恢复为 “收藏”
异常流程：
(1)未登录点击收藏 → 提示 “请先登录” 并跳转登录
(2)商品已下架或删除 → 提示 “该商品已失效，无法收藏”
(3)重复收藏同一商品 → 系统提示 “已收藏”，不重复插入数据
用例规约6：查看我的收藏
用例编号：UC006
用例名称：查看我的收藏
参与者：用户
前置条件：用户已登录，且存在收藏商品
后置条件：展示用户收藏的商品列表
基本流程：
(1)用户在个人中心点击 “我的收藏”
(2)系统请求收藏服务，查询当前用户收藏列表
(3)系统关联商品服务获取商品名称、图片、价格、实时库存
(4)分页展示收藏商品，支持点击跳转商品详情
(5)支持在收藏列表中直接取消收藏
异常流程：
(1)无收藏商品 → 展示空白页面并提示 “暂无收藏商品”
(2)商品已下架 → 列表中标记 “已下架”，禁止加入购物车
用例规约7：发表商品评价
用例编号：UC007
用例名称：发表商品评价
参与者：用户
前置条件：用户已登录，且存在已完成的订单商品
后置条件：评价成功发布，商品详情页展示该评价
基本流程：
(1)用户在 “我的订单” 中选择已完成订单
(2)点击 “评价商品” 按钮进入评价页面
(3)用户填写评分（1~5 星）、评价内容，可选择上传图片
(4)提交评价内容
(5)系统校验内容合法性，调用评价服务保存数据
(6)评价成功后，订单状态标记为 “已评价”
(7)商品详情页同步展示该条评价
异常流程：
(1)对未完成 / 未支付订单评价 → 提示 “订单未完成，无法评价”
(2)重复评价同一商品 → 提示 “已评价，不可重复提交”
(3)评价内容包含敏感词 → 拦截并提示 “内容不合法，请修改后重试”
(4)评价内容为空 → 提示 “请输入评价内容”
用例规约8：查看商品评价
用例编号：UC008
用例名称：查看商品评价
参与者：用户
前置条件：进入商品详情页
后置条件：展示该商品所有用户评价
基本流程：
(1)用户在商品详情页滑动或点击 “评价” 区域
(2)系统请求评价服务，按时间倒序查询该商品评价列表
(3)展示用户昵称（匿名处理）、评分、评价时间、文字及图片
(4)支持分页加载，展示好评、中评、差评筛选
(5)展示评价总数及平均星级
异常流程：
(1)该商品暂无评价 → 提示 “快来发表第一条评价吧”
(2)评价服务暂时不可用 → 提示 “评价加载失败，请稍后再试”
用例规约9：查看订单
用例编号：UC009
用例名称：查看订单
参与者：用户
前置条件：用户已登录系统且存在已创建的订单记录
后置条件：展示用户订单列表及订单详情信息
基本流程：
(1)用户进入个人中心，点击 “我的订单” 入口
(2)系统请求订单服务，查询当前用户所有订单数据
(3)按订单状态分类展示：待支付、待发货、待收货、已完成、已取消

(2)网络异常或服务超时 → 提示 “订单加载失败，请刷新重试”
(3)订单数据异常或不存在 → 提示 “订单不存在或已被删除”

3.3 模块化描述
系统按微服务拆分为高内聚、低耦合的独立模块，每个模块对应一个或一组服务。
3.3.1 用户模块
功能：用户注册、登录、身份验证、Token 管理
定位：系统统一身份入口
与架构关系：归属用户域聚类
3.3.2 个人中心模块
功能：资料管理、地址管理、订单 / 收藏 / 评价聚合展示
定位：用户操作聚合入口
与架构关系：归属用户域聚类
3.3.3 商品模块
功能：商品列表、详情、搜索、分类
定位：商品信息核心服务
与架构关系：归属商品域聚类
3.3.4 库存模块
功能：实时库存查询、库存扣减、库存回滚
定位：保证库存一致性核心
与架构关系：归属商品域聚类
3.3.5 购物车模块
功能：添加 / 删除 / 修改商品、实时计算金额
定位：交易前置缓冲层
与架构关系：归属交易域聚类
3.3.6 订单模块
功能：创建订单、订单状态流转、支付、与库存协同
定位：核心交易链路
与架构关系：归属交易域聚类
3.3.7 收藏模块
功能：收藏 / 取消收藏、收藏列表查询
定位：用户偏好运营服务
与架构关系：归属运营域聚类
3.3.8 评价模块
功能：发布评价、查询评价、评分统计
定位：商品反馈服务
与架构关系：归属运营域聚类
3.3.9 网关模块
功能：统一入口、路由、认证、限流
定位：前后端隔离层
与架构关系：独立网关层
3.3.10 公共基础模块
功能：注册发现、配置管理、分布式事务、监控
定位：全系统支撑服务
与架构关系：独立公共基础层
3.4 层次化抽象
系统自顶向下分为五层：前端层 → 网关层 → 业务微服务层 → 公共基础层 → 数据层。上层依赖下层，下层不依赖上层，职责清晰、易于维护。
3.5 聚类泛化抽象
业务服务按业务域聚类，同类服务内聚、不同域低耦合：
用户域：用户认证、个人信息
商品域：商品信息、库存
交易域：购物车、订单、支付
运营域：收藏、评价
聚类后可独立开发、独立部署、独立扩容。
四、非功能需求分析
4.1 可用性（Availability）
1. 系统全年可用率 ≥ 99.5%
2. 支持服务熔断、降级，单个微服务故障不影响整个商城使用
3. 支持滚动更新，不停机发布
4. 接口超时自动重试，提升容错能力
4.2 可修改性（Modifiability）
1. 基于微服务拆分，各模块独立开发、部署、维护
2. 商品、订单、购物车、用户服务解耦
3. 新增功能（如优惠券、秒杀）不影响现有核心业务
4. 代码结构分层清晰，易于维护与扩展
4.3 性能（Performance）
1. 商品列表、详情接口响应时间 < 200ms
2. 购物车、订单接口响应时间 < 300ms
3. 支持 500+ 用户并发操作
4. 库存查询采用缓存，保证实时性
5. 下单接口高并发下不阻塞、不超卖
4.4 安全性（Security）
1. 用户密码加密存储
2. 接口身份认证，防止未登录访问
3. 防重复提交订单
4. 防库存超卖、防恶意刷单
5. 防止 SQL 注入、XSS 攻击
6. 关键操作日志记录
4.5 可测性（Testability）
1. 微服务独立可测试
2. 提供单元测试、接口测试用例
3. 支持自动化测试脚本执行
4. 测试环境与生产环境隔离
5. 核心流程（下单 + 扣库存）可自动化回归测试
4.6 易用性（Usability）
1. 界面简洁，操作流程符合电商使用习惯
2. 按钮、文案清晰，减少用户理解成本
3. 购物车金额实时计算，无需手动刷新
4. 错误提示明确，引导用户下一步操作
5. 支持移动端、PC 端友好展示

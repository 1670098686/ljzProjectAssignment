# 在线商城系统项目生成提示词

## 一、项目概述

### 1.1 项目定位
基于微服务架构的在线商城系统，面向普通用户提供商品浏览、选购、加购、下单、支付、评价、收藏等全流程电商能力。

### 1.2 技术栈要求
- **前端**：PC 端网页（需兼容主流浏览器）
- **网关层**：Nginx（反向代理、负载均衡、路由转发）
- **微服务框架**：Spring Cloud Alibaba 或同等微服务框架
- **注册/配置中心**：Nacos
- **分布式事务**：Seata
- **数据库**：MySQL（主从架构）+ Redis 缓存
- **文件存储**：分布式文件存储系统

### 1.3 核心特性
- 微服务架构，高可用、易扩展
- 分布式事务保证数据一致性
- 支持多用户并发访问
- 实时库存管理，防止超卖

## 三、部署架构要求

### 3.1 物理部署架构
```
用户设备（PC/手机）
    ↓
负载均衡服务器（Nginx）
    ↓
应用服务器集群
├─ Gateway 集群
├─ 用户/个人中心服务集群
├─ 商品/库存服务集群
├─ 购物车/订单服务集群
└─ 收藏/评价服务集群
    ↓
中间件集群
├─ Nacos 注册配置中心
├─ Seata 分布式事务服务
└─ Redis 缓存集群
    ↓
数据库集群（MySQL 主从架构 + 分布式文件存储）
```

### 3.2 Nginx 配置要求

#### 基础配置
- **端口**：默认 80 端口（若被占用需调整）
- **根目录**：前端网页文件统一放置目录
- **配置文件命名**：mall-nginx.conf
- **日志**：开启访问日志和错误日志

#### 核心功能配置
1. **反向代理**：将请求转发至对应微服务
2. **负载均衡**：微服务集群部署时均匀分配请求
3. **路由规则**：
   - 商品查询 → 商品服务
   - 订单提交 → 订单服务
   - 收藏请求 → 收藏服务
4. **安全配置**：
   - 未登录用户限制访问个人中心、订单管理、收藏等页面
   - 限流规则：限制单 IP 单位时间访问次数
   - 禁止访问敏感资源（后台文件、配置文件）
5. **容错机制**：微服务故障时返回友好提示

### 3.3 前端部署规范
- 所有前端文件（HTML/CSS/JS/图片）放置于 Nginx 根目录
- 静态资源路径正确，无加载失败
- 支持响应式布局，适配 PC 端和移动端
- 页面跳转流畅，无 404/500 错误

## 四、核心业务流程

### 4.1 商品选购流程
```
用户浏览商品列表
  → 查看商品详情（含实时库存）
  → 加入购物车
  → 修改购物车数量（校验库存）
  → 结算生成订单
  → 分布式事务：创建订单 + 扣减库存 + 清空购物车
  → 支付模拟
  → 完成
```

### 4.2 分布式事务场景
**订单创建 + 库存扣减**（UC003）
- 开启 Seata 分布式事务
- 创建订单记录
- 扣减对应商品库存
- 清空购物车
- 提交事务（全部成功）
- **异常回滚**：库存不足或服务异常时，订单和库存自动回滚

### 4.3 收藏流程
```
用户登录
  → 商品详情页点击"收藏"
  → 校验登录状态
  → 添加至收藏列表
  → 按钮状态变更
  → 支持取消收藏
```

### 4.4 评价流程
```
用户登录
  → 查看已完成订单
  → 点击"评价商品"
  → 填写评分（1-5 星）+ 文字内容 + 可选图片
  → 提交评价（敏感词校验）
  → 保存评价数据
  → 订单标记为"已评价"
  → 商品详情页展示评价
```

## 五、非功能需求

### 5.1 性能指标
- 商品列表/详情接口响应时间 < 200ms
- 购物车/订单接口响应时间 < 300ms
- 支持 500+ 用户并发操作
- 库存查询采用 Redis 缓存，保证实时性
- 高并发下单不阻塞、不超卖

### 5.2 可用性要求
- 系统全年可用率 ≥ 99.5%
- 支持服务熔断、降级
- 单个微服务故障不影响整体功能
- 支持滚动更新，不停机发布
- 接口超时自动重试

### 5.3 安全性要求
- 用户密码加密存储（BCrypt 或同等）
- 接口身份认证（JWT Token）
- 防重复提交订单
- 防库存超卖
- 防 SQL 注入、XSS 攻击
- 关键操作日志记录
- 敏感操作（登录、支付）配置 HTTPS

### 5.4 可修改性要求
- 微服务独立开发、部署、维护
- 新增功能不影响现有业务
- 代码结构分层清晰
- 支持新增业务域（如优惠券、秒杀）

### 5.5 可测性要求
- 各微服务独立可测试
- 提供单元测试、接口测试用例
- 支持自动化测试
- 测试环境与生产环境隔离
- 核心流程可自动化回归测试

### 5.6 易用性要求
- 界面简洁，操作流程符合电商习惯
- 购物车金额实时计算，无需手动刷新
- 错误提示明确，引导用户下一步操作
- 支持移动端、PC 端自适应
- 导航清晰，按钮文案简洁

## 十一、关键注意事项

1. **分布式事务**：订单创建与库存扣减必须保证原子性，使用 Seata 确保数据一致
2. **库存超卖**：高并发场景下使用乐观锁或 Redis 分布式锁防止超卖
3. **身份认证**：未登录用户禁止访问个人中心、订单、收藏等页面
4. **限流降级**：Nginx 配置限流规则，防止恶意刷单
5. **响应式布局**：前端需适配 PC 端和移动端
6. **日志记录**：关键操作必须记录日志，便于问题排查
7. **HTTPS 配置**：登录、支付等敏感操作需配置 HTTPS 加密
8. **服务容错**：微服务故障时返回友好提示，不影响其他功能
